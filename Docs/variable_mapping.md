# Variable Mapping – P1-LC Control Loop (HAI ICS Dataset)

This document describes the mapping and interpretation of key process variables used in the analysis of the **P1-LC (Level Control)** subsystem within the HAI ICS dataset.

The purpose of this document is to clarify the **engineering meaning**, **security relevance**, and **analytical role** of each variable, rather than to enumerate all available dataset signals.

---

## 1. Subsystem Overview: P1-LC

P1-LC represents a **level control loop** responsible for maintaining the water level of a return water tank.

The control objective is to regulate the process variable (water level) to match a desired setpoint by adjusting a control valve.

---

## 2. Core Variable Categories

The analysis is structured around three fundamental control-system variable types:

| Category | Description | Security Relevance |
|--------|------------|-------------------|
| SP | Setpoint | Represents operator intent or attacker manipulation |
| PV | Process Variable | Reflects the physical process response |
| CV | Control Variable | Represents controller output and actuation behavior |

This SP–PV–CV abstraction is commonly used in both control engineering and ICS security analysis.

---

## 3. Variable Mapping Used in This Project

### 3.1 Setpoint (SP)

| Variable Name | Description |
|--------------|------------|
| `P1.B3004` | Operator-defined level setpoint for the P1-LC control loop |

**Interpretation:**

- Defines the target water level
- Changes may originate from legitimate operator actions or malicious manipulation
- Sudden or hidden SP changes can indicate setpoint-based attacks (e.g., SA08)

---

### 3.2 Process Variable (PV)

| Variable Name | Description |
|--------------|------------|
| `P1.LIT01` | Level indicator transmitter measuring water level |

**Interpretation:**

- Represents the actual physical state of the system
- Used by the controller as feedback input
- Discrepancies between SP and PV are central to control behavior analysis
- Replay or spoofing of PV values can mask real process deviations

---

### 3.3 Control Variable (CV)

| Variable Name | Description |
|--------------|------------|
| `P1.LCV01D` | Control command to the level control valve |

**Interpretation:**

- Generated by the controller based on SP–PV deviation
- Reflects control effort and system response
- Abnormal CV behavior may indicate controller manipulation or compensation for hidden disturbances

---

## 4. Normal SP–PV–CV Relationship

Under normal operation, the expected relationship is:

1. SP defines the desired level
2. PV tracks SP with minimal steady-state error
3. CV adjusts smoothly to maintain PV near SP

This baseline relationship is used as the reference for evaluating attack scenarios.

---

## 5. Security Interpretation of Variable Behavior

From an ICS security perspective:

- **SP anomalies** may indicate unauthorized command injection or HMI manipulation
- **PV inconsistencies** may indicate sensor replay or spoofing
- **CV deviations** may indicate controller parameter manipulation or hidden process disturbances

However, the absence of visible anomalies in any single variable does **not** guarantee the absence of malicious activity.

---

## 6. Variable Scope and Exclusions

The following were intentionally excluded from this project:

- Additional sensors or actuators outside the P1-LC loop
- Internal controller parameters
- Alarm or interlock signals
- Network-level variables (e.g., Modbus registers)

These exclusions were deliberate to maintain focus on **process-level observability**.

---

## 7. Relevance to Attack Scenarios

### SA08

- Primary target: `P1.B3004` (SP)
- Secondary effect: `P1.LIT01` (PV) replay
- Observable impact on `P1.LCV01D` (CV) may remain within normal bounds

---

### MA06 (Composed Attack: SA08 + SA14)

- Combines multiple manipulation strategies
- Effects may be distributed across SP, PV, and CV
- Individual stages may not produce conclusive anomalies in isolation

---

## 8. Summary

This variable mapping documents how specific HAI ICS dataset signals are interpreted within the scope of this project.

By explicitly defining variable roles and exclusions, the analysis avoids overgeneralization and supports transparent, reproducible security reasoning.
