# **ICS HAI Attack Analysis**

**Process-Aware Security Analysis of Industrial Control System Attacks**

## Project Overview

This repository contains a **process-aware security analysis** of industrial attack scenarios from the **HAI ICS dataset**, with a focus on understanding **normal control behavior** before evaluating potential attack impact.

Rather than assuming that attacks must immediately produce observable anomalies, this project emphasizes evidence-based interpretation and reflects the realities of industrial control system (ICS) incident investigation.

The analysis currently covers two attack scenarios:

**SA08** – Setpoint manipulation and sensor replay

**MA06** – Malicious modification of control parameters

## **Dataset Context**

The HAI ICS dataset represents a simulated industrial environment consisting of multiple process control loops (pressure, level, flow, temperature).
This project focuses on the **P1-LC (Level Control)** subsystem.

### Key variables analyzed:

* **SP (Setpoint)** – Operator or attacker-defined target value
* **PV (Process Variable)** – Sensor-measured physical process state
* **CV (Control Variable)** – Actuator command generated by the controller

The analysis intentionally uses a minimal-variable approach (SP–PV–CV) to preserve interpretability and reduce noise.

## **Methodology**

The analysis follows a disciplined, process-aware workflow:

1. **Establish normal behavior first**
Understand expected SP–PV–CV relationships under stable operation.
2. **Compare against attack data without presupposition**
Attack labels are not treated as proof of observable anomalies.
3. **Refuse unsupported conclusions**
If available evidence is insufficient, uncertainty is explicitly stated.

This approach mirrors real-world ICS security investigations, where premature attribution can lead to incorrect conclusions.

### **Analyzed Attack Scenarios**

#### **SA08 – Setpoint Manipulation & Sensor Replay**

* Target: P1-LC level control loop

* Attack intent: Increase setpoint using a trapezoidal profile while replaying sensor values to mask manipulation

##### **Key finding:**

Time-series analysis of SP, PV, and CV does **not provide conclusive visual evidence of abnormal behavior** at the analyzed stage.

This outcome highlights how early-stage or stealthy attacks may remain operationally invisible when only surface-level process signals are available.

#### **MA06 – Control Parameter Manipulation**

* Target: Internal controller parameters

* Attack intent: Alter control behavior without obvious external signal disruption

##### **Key finding:**

Observed differences remain subtle and insufficient for definitive attribution without deeper controller-level or model-based analysis.

### **Key Takeaways**

* Absence of visible anomalies does not imply absence of attack
* Rule-based or threshold-based detection may fail for stealthy ICS attacks
* Process understanding is critical for meaningful security interpretation
* Visual analysis alone is often insufficient for parameter-level attacks

## **How to Reproduce the Analysis**

Place the HAI dataset CSV files into data/
Install dependencies:
pip install -r requirements.txt

Run scenario-specific analysis:

python src/SA08.py
python src/MA06.py


Generated figures will be saved to Reports/Figures/.

## **Limitations**

* Only process-level time-series data was analyzed
* No network traffic or PLC logic was available
* No machine learning or automated anomaly detection was applied
* Ground-truth attack timing was not used
* These limitations intentionally reflect early-stage or constrained ICS investigations.

## **Future Work**

* Correlate process data with network traffic (e.g., Modbus write operations)
* Incorporate controller logic or parameter inspection
* Compare rule-based vs. model-based detection approaches
* Extend analysis to additional HAI attack scenarios
